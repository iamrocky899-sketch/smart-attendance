# SMART ATTENDANCE DATABASE — Google Sheets Schema

This document defines the exact database structure for the master Google Spreadsheet **`SMART ATTENDANCE DATABASE`** hosted on the dedicated Google Account:
**`attendancehalim@gmail.com`**.

---

## 1. Google Drive Directory Structure

Inside Google Drive (`attendancehalim@gmail.com`), create a root folder:

```
Google Drive /
└── SMART ATTENDANCE /
    ├── SMART ATTENDANCE DATABASE (Master Google Spreadsheet)
    ├── Workers/                  (Folder for worker documents/photos)
    ├── Attendance/               (Folder for attendance archives)
    ├── Reports/                  (Folder for daily/monthly exported reports)
    └── Backend Documentation/    (Folder for system backups and schema docs)
```

---

## 2. Master Google Spreadsheet Tabs & Columns

The master spreadsheet **`SMART ATTENDANCE DATABASE`** contains exactly 5 tabs:

---

### Tab 1: `Workers`
Stores master worker profiles, employment details, password hashes, and active states.

| Column Index | Column Name | Data Type | Example Value | Description |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `workerId` | String | `EMP-0001` | Unique sequential identifier generated by backend (`EMP-0001`, `EMP-0002`...) |
| **B** | `workerName` | String | `Rahul Das` | Full name of the worker |
| **C** | `mobileNumber` | String | `9876543210` | Contact phone number |
| **D** | `workplace` | String | `Gameri HS` | Assigned facility, school, or project site |
| **E** | `designation` | String | `Field Staff` | Job title or role |
| **F** | `joiningDate` | String | `2026-01-15` | Date of joining (`YYYY-MM-DD`) |
| **G** | `passwordHash` | String | `5994471abb01112afc18159f6cc74b4f511b99806da59b3caf5a9c173cacfc5` | SHA-256 hashed password (initial `12345`) |
| **H** | `status` | String | `ACTIVE` | Account status (`ACTIVE` or `INACTIVE`) |
| **I** | `createdAt` | String (ISO) | `2026-08-23T08:00:00.000+05:30` | Server creation timestamp in `Asia/Kolkata` |
| **J** | `updatedAt` | String (ISO) | `2026-08-23T08:00:00.000+05:30` | Last updated timestamp |

> [!IMPORTANT]
> - **Dual Login Identifiers**: Workers can log in using either their `workerId` (e.g. `EMP-0001`) OR their registered `mobileNumber` (e.g. `9876543210`).
> - **Mobile Number Uniqueness**: Mobile numbers must be unique across all workers. The backend rejects creation or update of accounts with duplicate mobile numbers.
> - **Normalization**: Mobile numbers are normalized by stripping all non-digits, country code prefixes (`+91` / `91`), and leading zeros before storing and lookup.
> - **Password Security**: Never store plaintext passwords. The initial default password `12345` is stored as its salted SHA-256 hash.
> - **Deactivation**: Deactivating a worker sets `status = INACTIVE`. Workers with `INACTIVE` status cannot log in or record attendance, but their profile and past attendance records are permanently preserved.

### Tab 2: `Attendance`
Stores immutable attendance punch events (Punch In, Punch Out, and Admin Manual entries).

| Column Index | Column Name | Data Type | Example Value | Description |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `attendanceId` | String (UUID) | `c68f1234-5678-4321-abcd-ef0123456789` | Unique record/request ID generated by client/backend |
| **B** | `workerId` | String | `EMP-0001` | Employee ID |
| **C** | `workerName` | String | `Rahul Das` | Worker's full name at time of attendance |
| **D** | `attendanceType` | String | `PUNCH_IN` | Event type: `PUNCH_IN`, `PUNCH_OUT`, or `MANUAL` |
| **E** | `timestamp` | Number (Epoch) | `1755998400000` | Device epoch timestamp (milliseconds) |
| **F** | `date` | String | `2026-08-23` | Attendance date (`YYYY-MM-DD`) |
| **G** | `time` | String | `08:30:15` | Attendance time (`HH:mm:ss`) |
| **H** | `latitude` | Number | `26.758412` | Single-shot GPS Latitude (-90 to +90) |
| **I** | `longitude` | Number | `93.125678` | Single-shot GPS Longitude (-180 to +180) |
| **J** | `accuracy` | Number | `14.5` | GPS accuracy radius in meters |
| **K** | `localArea` | String | `Gameri, Biswanath` | Resolved reverse-geocoded address / place name |
| **L** | `syncSource` | String | `WORKER_APP` | Source of entry: `WORKER_APP` or `ADMIN_APP` |
| **M** | `createdByAdminId` | String | `admin` | Admin ID if manual entry (empty for worker punch) |
| **N** | `createdByAdminName` | String | `Administrator` | Admin Name if manual entry (empty for worker punch) |
| **O** | `notes` | String | `Field visit duty` | Reason/Note (required for manual attendance) |
| **P** | `createdAt` | String (ISO) | `2026-08-23T08:30:16.120+05:30` | Server receipt timestamp in `Asia/Kolkata` |
| **Q** | `updatedAt` | String (ISO) | `2026-08-23T08:30:16.120+05:30` | Last updated timestamp |

> [!NOTE]
> - `PUNCH_IN` and `PUNCH_OUT` are stored as separate immutable row records.
> - There is NO geo-fencing. Any valid GPS coordinate is accepted.

### Tab 3: `Admins`
Stores authorized administrator credentials and access profiles.

| Column Index | Column Name | Data Type | Example Value | Description |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `adminId` | String | `ADMIN-0001` | Unique admin identifier |
| **B** | `adminName` | String | `System Administrator` | Full administrator name |
| **C** | `mobileNumber` | String | `6003090734` | Registered Admin Mobile Number (used for login) |
| **D** | `passwordHash` | String | `5994471abb01112afc18159f6cc74b4f511b99806da59b3caf5a9c173cacfc5` | Salted SHA-256 hash of initial password `12345` |
| **E** | `status` | String | `ACTIVE` | `ACTIVE` or `INACTIVE` |
| **F** | `createdAt` | String (ISO) | `2026-08-23T08:00:00.000+05:30` | Server creation timestamp |
| **G** | `updatedAt` | String (ISO) | `2026-08-23T08:00:00.000+05:30` | Last updated timestamp |

> [!IMPORTANT]
> - **Admin Login Identifier**: Administrators log in using their registered `mobileNumber` (`6003090734`) or `adminId` (`ADMIN-0001`) with default initial password `12345`.
> - The Gmail account `attendancehalim@gmail.com` is purely the backend owner and controller. It is NEVER used as an application login identifier or password.

### Tab 4: `Settings`
Key-value configuration store for application-wide policies and parameters.

| Column Index | Column Name | Data Type | Example Value | Description |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `key` | String | `timezone` | Unique configuration key |
| **B** | `value` | String | `Asia/Kolkata` | Configuration value |
| **C** | `updatedAt` | String (ISO) | `2026-08-23T08:00:00.000+05:30` | Timestamp of last modification |

#### Initial Prepopulated Rows:
1. `appName` $\rightarrow$ `SMART ATTENDANCE`
2. `timezone` $\rightarrow$ `Asia/Kolkata`
3. `attendancePolicy` $\rightarrow$ `ANY_LOCATION`
4. `workerInitialPasswordPolicy` $\rightarrow$ `12345`
5. `backendVersion` $\rightarrow$ `1.0.0`
6. `tokenExpiryHours` $\rightarrow$ `720` (30 days)

### Tab 5: `SyncLog`
Audit log for offline synchronization requests, duplicate detection, and troubleshooting.

| Column Index | Column Name | Data Type | Example Value | Description |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `syncId` | String (UUID) | `log-1755998400-001` | Unique log entry ID |
| **B** | `requestId` | String | `c68f1234-5678-4321-abcd-ef0123456789` | Client attendance / request ID |
| **C** | `workerId` | String | `EMP-0001` | Worker or Admin ID who initiated the call |
| **D** | `operation` | String | `createPunchIn` | API operation name |
| **E** | `status` | String | `SUCCESS` | `SUCCESS`, `DUPLICATE_IGNORED`, or `FAILED` |
| **F** | `message` | String | `Punch in saved successfully` | Result summary |
| **G** | `timestamp` | String (ISO) | `2026-08-23T08:30:16.120+05:30` | Server log timestamp |

> [!CAUTION]
> Under no circumstances should passwords, session tokens, or private secrets be logged into `SyncLog`.
